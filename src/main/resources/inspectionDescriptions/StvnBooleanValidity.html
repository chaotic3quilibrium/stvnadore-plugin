Identifies non-canonical boolean casing and invalid literal tokens placed in slots constrained by :Boolean schemas.

In STVN, boolean literals are strictly case-sensitive keywords belonging to the Variable/Value track (#). Valid forms are limited exclusively to:

  • Long-form: #TRUE, #FALSE
  • Short-form: #T, #F

Common casing near-misses such as #True, #False, #true, or #false, as well as unquoted identifiers or invalid tokens placed in boolean slots, are reported as errors.

Quick-Fixes Available:

  • Change tag to #TRUE / #FALSE / #T / #F: Instantly corrects near-miss casing errors to the project-preferred canonical form.
  • Change to boolean literal: Replaces invalid tokens with a valid boolean literal placeholder.

Example (Invalid Casing):

{
  :type :Boolean
  // Error: Invalid boolean literal casing: '#True'
  :body #True
}

Valid Canonical Forms:

{
  :type :Boolean
  :body #TRUE   // Canonical uppercase long-form
  // or: #T     // Canonical uppercase short-form
}
