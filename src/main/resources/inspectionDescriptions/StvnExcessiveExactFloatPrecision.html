Reports declared mantissa precision on exact decimal float types ({ #exact } :Float) that exceeds the configured warning threshold (default: 38 significant decimal digits).

Under STVN Language Specification § 5.1.3 and § 6.1, facet #maxSize <N> specifies the maximum allowable count of significant decimal digits in the unscaled mantissa, carrying an intrinsic default ceiling of 16,777,216 digits.

Developers frequently confuse mantissa precision with numeric value bounds, declaring #maxSize 100, #maxSize 1000, or #maxSize 10000 under the mistaken belief that it restricts numerical magnitude. Multi-thousand digit decimal calculations cause severe CPU and memory performance degradation.

Compliant Examples:

// Compliant: Standard financial precision (≤ 38 digits)
:Price { #exact #maxSize 18 } :Float
:Currency { #exact #maxSize 38 } :Float

// Compliant: Numerical magnitude bound instead of mantissa precision
:BoundedAmount { #exact #minIncl 0.0 #maxExcl 1000.0 } :Float

Warning Example:

// Warning: Declared mantissa precision of 1000 digits is unusually large
:BadPrice { #exact #maxSize 1000 } :Float

Available Quick-Fixes:

  • Clamp #maxSize to 38: Replaces the declared numeric precision with 38 (standard ANSI SQL DECIMAL(38, s) and IEEE 754-2008 decimal128 hardware boundary).
  • Convert to numeric bound '#maxExcl ': Replaces #maxSize <N> with #maxExcl <N>.0 for schemas where a numeric range limit was intended.
