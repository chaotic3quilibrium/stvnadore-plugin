Reports payload values in the :body block that are bound to degraded nominal schemas whose metadata constraints or lineage failed validation in :defs, causing Pass 3 payload evaluation to be suspended.

When an STVN schema definition contains invalid metadata constraints (such as an invalid regex pattern in #regex, inapplicable facets, or contradictory bounds) or an unresolved/circular lineage, the STVN compiler marks the nominal schema as a PoisonedSchema. Grounded degraded schemas retain their underlying fallback base type strictly for Pass 2 child type derivation in :defs and structural display context, while Pass 3 suspends :body payload evaluation for all degraded schema slots.

Inspection Options:

  • Highlight body values bound to degraded schemas: When enabled, every leaf value in the document payload bound to a degraded schema is highlighted with a weak warning, identifying the affected schema, its underlying base type (when grounded), and the suspension of payload evaluation. When disabled (default), degraded schema errors are reported only at the definition site in :defs (and anchored as warnings in :type).

Example (Degraded Schema):

{
  :defs {
    // Tier 1 Error: Invalid regex pattern syntax degrades schema to :String
    :BrokenRegex { #regex "[" } :String
  }
  :type :BrokenRegex
  :body "payload_value" // Highlighted as weak warning when option is enabled
}

How to Fix:

Correct the invalid metadata constraint in the nominal definition within :defs to restore full schema validation:

{
  :defs {
    :ValidRegex { #regex "[a-z]+" } :String
  }
  :type :ValidRegex
  :body "payload_value"
}
