Reports payload values in the :body block that are bound to degraded nominal schemas whose metadata constraints or lineage failed validation in :defs, causing Pass 3 payload evaluation to be suspended.

When an STVN schema definition contains invalid metadata constraints (such as an invalid regex pattern in #regex, conflicting mutually exclusive facets, incomplete trait facets, or contradictory bounds) or an unresolved/circular lineage, the STVN compiler marks the nominal schema as a PoisonedSchema. Grounded degraded schemas retain their concise underlying base constructor fallback (such as :String, :Int, or :Enum without inline variant lists) strictly for Pass 2 child type derivation in :defs and structural hover context, while Pass 3 suspends :body payload evaluation for all degraded schema slots.

Inspection Options:

  • Highlight body values bound to degraded schemas: When enabled, every leaf value in the document payload bound to a degraded schema is highlighted with weak warning PW006, identifying the affected schema, its concise underlying base type (when grounded), and the suspension of payload evaluation. Hovering over a degraded :body value renders the yellow Degraded Schema Warning banner while preserving Ctrl+Click symbol navigation.

Example (Degraded Schema):

{
  :defs {
    // Tier 1 Error: Invalid regex pattern syntax degrades schema to :String
    :BrokenRegex { #regex "[" } :String
  }
  :type :BrokenRegex
  :body "payload_value" // Highlighted as weak warning when option is enabled
}

How to Fix:

Correct the invalid metadata constraint in the nominal definition within :defs to restore full schema validation:

{
  :defs {
    :ValidRegex { #regex "[a-z]+" } :String
  }
  :type :ValidRegex
  :body "payload_value"
}
