Reports payload values in the :body block that are bound to nominal schemas whose metadata constraints failed validation in :defs (Tier 1 constraint errors) and are operating on fallback primitive base types.

When an STVN schema definition contains invalid metadata constraints (such as an invalid regex pattern in #regex, out-of-range numeric limits, or contradictory constraints), the STVN compiler degrades the nominal schema to its primitive base type to permit continued AST parsing and editing.

Inspection Options:

  • Highlight body values bound to degraded schemas: When enabled, every leaf value in the document payload bound to a degraded schema is highlighted with a weak warning, identifying the affected schema and the fallback base type in use. When disabled (default), degraded schema errors are reported only at the definition site in :defs.

Example (Degraded Schema):

{
  :defs {
    // Tier 1 Error: Invalid regex pattern syntax degrades schema to :String
    :BrokenRegex { #regex "[" } :String
  }
  :type :BrokenRegex
  :body "payload_value" // Highlighted as weak warning when option is enabled
}

How to Fix:

Correct the invalid metadata constraint in the nominal definition within :defs to restore full schema validation:

{
  :defs {
    :ValidRegex { #regex "[a-z]+" } :String
  }
  :type :ValidRegex
  :body "payload_value"
}
